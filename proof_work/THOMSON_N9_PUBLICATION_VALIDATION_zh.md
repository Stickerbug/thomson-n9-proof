# Thomson n=9 投稿前验证评估

本文评估的是已有九点证明候选的可信度与发表准备度，不新增九点最优性证明。当前材料仍属于会话内复算通过、尚无外部独立验证的证明稿。以下外部项目情况依据实际读取的仓库材料；本次没有安装、编译或运行其 Lean 证明。

## 1. 结论

需要更严格的验证。目前同一套 Python/C 算术和域细分实现重复运行，能验证可复现性，不能排除共享实现错误。Lean 并非所有数学期刊的统一发表门槛；但对于九点这一长期开放问题，建议以“可读数学证明 + 独立精确检查器 + Lean 最终定理 + 第二内核 + 外部专家审阅”为目标。

技术上可以按七点项目的标准建设；目前尚未做到，无法保证形式化后一定成功。形式化暴露的数学漏洞必须修正，不能通过添加新公理或弱化主定理掩盖。

## 2. 七点项目实际提供什么

核查快照：huwngtran/thomson-n7-lean，commit 25f2fa53119273458cfbb3c4230904bffdd61e53。

- [README](https://github.com/huwngtran/thomson-n7-lean/blob/25f2fa53119273458cfbb3c4230904bffdd61e53/README.md)
- [定理陈述](https://github.com/huwngtran/thomson-n7-lean/blob/25f2fa53119273458cfbb3c4230904bffdd61e53/info/CLAIM.md)
- [复算要求](https://github.com/huwngtran/thomson-n7-lean/blob/25f2fa53119273458cfbb3c4230904bffdd61e53/REPRODUCE.md)
- [主检查脚本](https://github.com/huwngtran/thomson-n7-lean/blob/25f2fa53119273458cfbb3c4230904bffdd61e53/formal/lean/scripts/check.sh)
- [第二内核检查](https://github.com/huwngtran/thomson-n7-lean/blob/25f2fa53119273458cfbb3c4230904bffdd61e53/formal/lean/scripts/second-kernel.sh)

其目标是七个互异单位球点的 Coulomb 全局最优，以及模 O(3) 和重标号的唯一性；不是只证明对称族最优或局部最优。

数学上，它按最小点积 m 分域：m≥−0.9 用三点半正定界；五个区间覆盖 [−0.99,−0.9]；m≤−0.99 使用带类型的核、近等号刚性及严格局部分析。核的构造搜索不需要被信任，最终精确整数/有理证书需要被核验。

仓库报告：

1. Lean 4.34.1 和固定 Mathlib commit d13f23b723b8a846827a245b89c10fc7d3f11612；主证明约17,895行。
2. 完整解答中的数值证明使用 `decide +kernel`；不是依靠 Python 返回 True 作为 Lean 前提。
3. 最终定理公理依赖为 `propext`、`Classical.choice`、`Quot.sound`。
4. 固定挑战陈述，与解答的定义和定理作比较；避免形式化时偷偷改题。
5. 用独立 Rust 内核 nanoda 检查导出的证明，并报告检查47,854个声明无误。
6. 两类负向测试：翻转目标不等式应被陈述比较拒绝；篡改导出证书的一个整数应被第二内核拒绝。
7. 提供正文引理到 Lean 声明的映射、哈希清单及构建日志。

这些成功记录属于作者发布的证据；本次未亲自重建。仓库本身仍标明未同行评审、陈述未获人工认证。形式化检查也不能代替人工确认形式化陈述恰好表达原问题。

还有具体可改进点：主脚本的危险词扫描使用 `grep ... || true`，命中只显示而不自动失败；主脚本的公理检查只拒绝几个指定名称，没有强制精确白名单。不过第二内核脚本设置了严格允许公理列表和 `unpermitted_axiom_hard_error: true`。不能因此断言其定理错误；我们应借鉴严格白名单并把所有门槛变成自动失败。

## 3. 八点项目的额外参考

核查快照：lukasliehr/Energy-Minimization-8-Points，commit 50d14bc06bd41f61573eb6a36eedb8d00759af8f。

[仓库说明](https://github.com/lukasliehr/Energy-Minimization-8-Points/blob/50d14bc06bd41f61573eb6a36eedb8d00759af8f/README.md)区分：Coulomb、对数势和充分大 Riesz 指数的定理已有 Lean 证明；所有非负指数的完整结果另有严格计算机辅助证书，但尚未全部在 Lean 中形式化。

[Coulomb 证书说明](https://github.com/lukasliehr/Energy-Minimization-8-Points/blob/50d14bc06bd41f61573eb6a36eedb8d00759af8f/Certificates/Coulomb/README.md)公开了只依赖 Python 标准库的精确检查器，并明确“Python success is not used as a hypothesis or axiom in Lean”。这正是九点项目值得采用的双重验证结构。其证书使用192个矩阵坐标及99×99精确线性修正，说明包含真参数修正的方案可以被形式化；但九点的33行修正和域覆盖仍需独立证明，不能直接套用其定理。

传统严格计算机辅助证明也可作为学术成果：例如 [Schwartz 五点论文](https://arxiv.org/abs/1001.3702)。不能把“有 Lean”当作所有发表工作的唯一标准，也不能把“没有 Lean”当作当前检查已经足够。

## 4. 九点项目与目标标准的差距

| 项目 | 当前九点材料 | 下一验收目标 |

节点数量、日志哈希和空栈是现有实现的执行记录；它们本身不是独立可验证的域覆盖证明。

## 5. 建议实施顺序与明确完成标准

### A. 冻结真正要证明的数学陈述

九个互异点、每点范数1、空间为实三维 EuclideanSpace、每条无序边只计一次、势为1/距离。竞争构型不能附加对称性或驻点假设。候选参数是(0,1)内唯一驻点，不是有限小数。冻结最优性定理；唯一性另立。

尤其要处理 Lean 中零的逆等于零的约定：必须要求互异点，或另行使用带无穷能量的定义。定理陈述需要人工审查，Comparator只能保证与冻结陈述一致。

### B. 把搜索结果改为可移交的证明证书

导出完整树：每个内部节点的分裂轴及两个子域；每个叶子的精确盒、终止理由、乘子或局部证书编号。检查器验证根域、无遗漏覆盖、所有边界及每个叶子的数学理由，不能直接信任 `status`、`pending=0` 或日志哈希。分裂边界允许重合，但必须证明子域并集等于父域；不能无解释地删除任何叶。

### C. 编写独立精确检查器

不用现有区间类、Bernstein转换、signed128/C助手或原覆盖循环。优先使用任意精度整数/有理数，直接从叶域和原始多项式计算 Bernstein 系数。重新检查配对归约、真根隔离、接触修正、PSD、Hermite下界和12个局部盒。速度可以慢，正确性与独立性优先。完整运行通过后，才称“独立实现复核通过”。

### D. 分层形式化

先证明通用数学层：三点PSD求和、重复指标计数、总能量恒等式、Gram域及对称归约；再证明真根存在唯一、33行系统与45条件的精确兼容性、Hermite转移和局部边界论证；最后证明检查器可靠性并在内核中核验具体证书。输出格式是 `check cert = true` 加上已证明的 `check cert = true → global_theorem`，不能添加 `axiom certificate_is_valid`。

只形式化数值算术或检查器程序，没有把它连接到最终九点定理，并不等于完成形式化证明。使用外部原生计算时必须披露额外信任；目标是内核可重验的证明对象。

### E. 第二内核、负向测试、干净重建

严格白名单仅允许标准基础公理，解答依赖中不能有 `sorryAx` 或新证书公理。危险项扫描、公理检查和定义比较都应失败即停止；占位挑战文件与完整解答分开。建立干净 CI 和至少一个独立机器上的完整构建。

负向测试至少包含：删叶造成漏域；伪造终止类型；局部盒越界；错的根括区；把非sharp目标冒充δ=0；以及已知在合法点残差为负的旧核。针对已知无效证书，检查器必须拒绝或返回未完成，绝不能成功。单纯改变任何一个整数不一定使数学证书失效，所以需要分别测试文件完整性拒绝和数学有效性拒绝。

### F. 外部审阅与发表

先整理英文稿、完整引理依赖、证书规格、代码许可、版本锁和公开可引用归档；请球面能量/半正定方法及形式化专家分别审阅数学和实现。对外联系、上传预印本和投稿属于后续行动，本次没有执行。明确引用Cohn–Woo等方法来源，并按目标期刊要求披露AI辅助。形式化成功不能自动保证创新性判断、同行评审或接收。

## 6. 能做到“更好”的可检验含义

目标可以是：同时具有独立Python检查、Lean最终定理、第二内核、严格自动失败CI、完整可移交覆盖证书、负向测试、公开版本归档和外部数学审查。更高精度、更多代理、更多重跑不能替代这些标准。
